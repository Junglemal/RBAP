# HW5
Кристина, добрый день! Загружаю задание по 5 уроку.

В работе сервис по работе и анализу отзывов, поэтому параллельно изучаю разные подходы к задачам. На текущий момент их две: определение тональности отзыва и саммаризация отзыва. В данном уроке продолжил экспериментировать с подходами к моделям и данными, постарлся учесть все требования к домашнему заданию. Хотя, конечно в условиях ограниченного времени, много ресурсов ушло на работу и изучение саммаризации LLM и апробированию LLM-as-a-Judge.

- Настроен пайплайн обработки сырых данных из парсера на уровне Pandas и функций (в последствии это всё будет .а) оптимизировано на уровне логики парсера .б) зашито в нормальную фукнцию перед загрузкой в БД. В работу с моделями применялась логика предобработки данных через функции.

- Усложнил подход, перешёл от статистических подходов: TF-IDF + текстовые статистики, к генерации эмбеддингов. Использовал векторизацию с помощью SBERT, RuBERT-Tiny2.

- Внедрены улучшенные модели для определения тональности, также добавлены две новые модели к имеющимся LR и RFC с 4 урока: Catboost и попробовал использовать предобученную модель с HF - rubert-tiny-sentiment-balanced (как раз выделяет три класса тональности). Для catboost использовалась кросс-валидация.

- В задаче тегирования и саммаризации отзывов, также усложнил подход. Было увеличено количество отзывов до 500 для обработки и получения метрик. Помимо Gemma3:4b пробовал использовать Qwen3:4b (модель постоянно падала в ошибку на запросах в ollama, решил отказаться от тестов с ней и перейти к модели с большим количеством параметров) и Gemma3:12b. Судьей для консистентности осталась Gemam3:27b.  

Итого следующими этапами требуется:

3. Дозагрузить пул отзывов ещё за два года, провести обучение Catboost модели на бОльшем объеме данных.
4. Поэксперементировать с промптом саммаризации. Доработать формат сохранения в JSON.
5. Сборка MVP в 6 уроке.

# HW4 + подход с консультации
MFDP: Review based analytical platfrom

Данные собраны парсером для актуальности и конкретного продукта - ипотеки (датасет с отзывами с banki.ru за 2023 год есть на HF).

EDA_baseline ноутбук содержит разведочный анализ данных, отчистку данных, а также базовый подход к определению тональности (3 класса: позитив, нейтральный, негатив).  Для тональности использованы две модели с выводом нескольких метрик. Улучшение моделей и подхода в модуле MFDP предполагается в 5 уроке (попробую grid search и другие модели, в т.ч. catboost планирую добавить).

Вторая часть данного урока по саммаризации текста находится в файлах:
1 - EDA_baseline_part2.jpynb - результаты саммаризации и оценки
2 - EDA_baseline_summary.py - код для саммаризации
3 - deep_eval_tests.py - LLM-as-a-Judge

В данной части тестируем саммаризацию, начиная с простых моделей (gemma3:4b) на небольшом количестве отзывов, чтобы определить как построить пайплайн обработки. Вторым этапом пробуем в работе библиотеку deepeval, которую обсуждали на консультации. Deepeval применяем для внедрения LLM-as-a-Judge, модель судья - Gemma3:27B. Модели используем через интерфейс ollama.

Таким образом, рабочее решение есть. Теперь в 5 уроке требуется масштабировать подход на большую выборку (~1000 отзывов) и внедрить вторую LLM с большим количеством параметром (8-12b) для сравнения работы моделей.
